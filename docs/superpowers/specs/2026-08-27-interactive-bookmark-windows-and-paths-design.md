# 可互動書籤視窗與任意路徑設計

## 目標

書籤列必須能直接以右鍵新增、改名、編輯及刪除邏輯書籤資料夾與檔案／資料夾路徑書籤。現有嵌在 Explorer 主畫面中的書籤管理員覆蓋層不可作為管理介面；管理員與書籤編輯器都必須使用可聚焦、可輸入、可獨立關閉的 GPUI 原生視窗。

## 互動決策

- 書籤列空白區右鍵顯示「新增資料夾」、「新增路徑書籤」與「書籤管理員」。
- 邏輯資料夾右鍵顯示新增子資料夾、新增路徑書籤、重新命名及刪除。
- 路徑書籤右鍵顯示開啟、編輯／改名及刪除；資料夾目標仍可在新分頁開啟。
- 「連結」只代表 SuperExplorer 可開啟的檔案、資料夾、遠端或虛擬路徑，不支援網站 URL。
- 新增路徑書籤預填目前選取項目；沒有選取時預填目前位置。使用者可自行改寫名稱與完整目標文字。

## 視窗與元件邊界

建立專用 `BookmarkManagerWindow`，由應用程式層以與既有 `BookmarkEditorWindow` 相同的 observer／`open_window` 模式建立。主視窗僅保存書籤樹、草稿、mutation 與通知狀態；管理視窗持有自己的焦點、輸入 entity 與視窗生命週期，所有命令仍回送主 `ExplorerRoot` reducer，因此耐久寫入與 rollback 只有一個權威入口。

既有 `BookmarkEditorWindow` 擴充為所有 typed bookmark 的共用新增／編輯視窗。Lua 顯示可編輯 source；Folder/File 顯示可編輯 target text，不再使用唯讀摘要。邏輯書籤資料夾改名也在獨立視窗或管理視窗內的可聚焦輸入流程完成，不再依賴主視窗 overlay。

## 路徑資料與錯誤策略

Folder/File bookmark 的 payload 仍使用既有 typed `LocationDescriptor`，但編輯器以可往返的顯示字串呈現。儲存只要求名稱與目標文字非空，不檢查目標存在，也不因當下無法解析或格式錯誤而拒絕。對不能立即轉成既有結構化 location 的輸入，模型保存原始使用者文字，使重新開啟編輯器時完全保留；實際啟用時才嘗試解析／開啟並顯示錯誤通知。這確保離線遠端、尚未掛載磁碟、未建立路徑與刻意保留的錯誤路徑皆可持久化。

## 持久化、生命週期與錯誤處理

新增、編輯、改名與刪除都先產生可 rollback 的 bookmark mutation，再要求現有 durable session 寫入。寫入失敗時回復 mutation、保留視窗與草稿並顯示通知；成功後才關閉相應草稿。重複開啟管理員時啟用既有視窗，主視窗關閉時清理子視窗 handle。刪除非空邏輯資料夾沿用 descendant count 確認，不碰觸實體檔案系統。

## 驗證

- 模型測試：原始錯誤路徑可序列化、還原、編輯且不被正規化遺失。
- UI state 測試：新增／編輯 Folder/File payload、資料夾 CRUD、刪除確認及 rollback。
- 視窗測試：管理員與編輯器有獨立 window options、可聚焦輸入及關閉／重開生命週期。
- Chrome 測試：不再渲染管理員 overlay；書籤列空白區、資料夾與書籤右鍵命令完整。
- 執行 `cargo fmt`、相關 crate 聚焦測試與可行的 `cargo check`。

## 非目標

不支援網站 URL、雲端同步、匯入匯出或對書籤目標執行建立／刪除檔案系統項目的操作；不改變 Lua 權限模型。
