## Context

專案目前已有 Windows 批次檔，但沒有統一的 AI 輔助 Git 提交流程。本變更需要在不實際執行提交或推送測試的前提下，提供一個可攜、單檔且可明確回報失敗的入口。

## Goals / Non-Goals

**Goals:**

- 從任何啟動位置都以專案根目錄作為工作目錄。
- 使用 Codex Spark 快思模型非互動執行既定中文提示詞。
- 指示代理只提交既有有效改動、排除產物、分類提交、處理 submodules 並推送。
- 將 Codex CLI 的成功或失敗反映到批次檔退出碼。

**Non-Goals:**

- 不自行在批次檔實作 Git 分類或暫存檔偵測邏輯。
- 不新增 PowerShell、提示詞或設定檔。
- 不保證在未登入 Codex、沒有 push 權限或遠端分支設定錯誤時仍可完成。

## Decisions

- 採用單一 `commit.bat` 內嵌提示詞，避免維護額外檔案；提示詞以 UTF-8 Base64 儲存在純 ASCII 批次檔中，執行時解碼至 stdin，避免 Windows `cmd.exe` 因檔案編碼或換行格式破壞中文命令列。
- 使用 Codex 的 `exec` 子命令而非互動模式，確保批次流程可無人值守完成；`-a` 等全域選項放在 `exec` 前，符合目前 CLI 的參數解析規則。
- 使用 `-C "%~dp0."` 鎖定工作目錄，避免依賴呼叫者目前所在路徑；尾端的 `.` 可防止 `%~dp0` 的反斜線干擾原生程式引數引號。
- 使用 `-m gpt-5.3-codex-spark` 與 `-c model_reasoning_effort="low"` 明確選擇快思設定。
- 使用 `-s danger-full-access -a never`，因 commit 與 push 需要寫入 Git metadata 及網路存取；安全邊界由固定提示詞限制為目前倉庫的 Git 操作。
- 讓 Codex 負責分析 Git 狀態及提交順序，批次檔只負責啟動與傳遞退出碼，以維持單檔簡潔。

## Risks / Trade-offs

- [代理可能錯分改動] → 提示詞要求先完整檢查狀態與 diff，再按功能關聯分組。
- [誤收產物或暫存檔] → 明確禁止提交編譯、建置、測試及工具產物，並要求不修改現有檔案。
- [danger-full-access 權限較大] → 固定工作目錄與狹義提示詞，且腳本須由使用者主動執行。
- [模型名稱或 CLI 選項未來改變] → 讓 CLI 直接回傳非零退出碼，以便快速察覺相容性問題。
- [無法安全做端到端測試] → 僅做語法和內容靜態驗證，不在開發期間執行會 commit/push 的批次檔。
