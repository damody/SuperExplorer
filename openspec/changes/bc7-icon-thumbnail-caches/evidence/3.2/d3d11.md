# G-D3D11 status

The Windows atlas checks `DXGI_FORMAT_BC7_UNORM` texture2D shader-sample capability, validates descriptor/layout/pitch, creates the immutable BC7 texture and SRV, uploads complete block rows directly, and uses logical UV bounds. Hits promote same-kind LRU recency and insertion evicts least-recent same-kind resources before crossing its limit. Device invalidation clears resources and LRU metadata.

Device-loss recovery clears both compressed texture lists, tile handles, byte costs, recency, and published usage, then the window forces its first recovered frame past the view cache. Visible `RenderImage` values retain immutable compressed blocks, so normal `paint_image` admission reconstructs fresh-device textures during that forced frame; no filesystem or Shell re-query is required for reconstruction.

Late-result protection is enforced at every ownership boundary: the Host job checks cancellation and generation before atomic publication, the UI request-context gate rejects superseded responses, and the visible compressed-image LRU rejects older association/overlay generations. Focused tests `compressed_texture_cannot_replace_a_newer_generation` and `qos_same_icon_key_rejects_a_superseded_request_context` both pass; device recovery clears all old-device atlas handles before the forced reconstruction frame.

The LRU bookkeeping is now a separate residency ledger with exact per-kind block-byte and entry accounting, promotion, removal acknowledgement, and direct-upload/eviction counters. `cargo test -p gpui --lib --locked --offline assets::tests -- --nocapture --test-threads=1` passes 3/3 descriptor, logical-size, and instrumentation tests. `cargo test -p gpui_windows --lib --locked --offline -- --nocapture --test-threads=1` passes 7/7, including independent LRU promotion/eviction/release accounting.

The gate remains partial: a limit reduction is applied on the next atlas access because the process-wide setter has no atlas instance, not synchronously at setter call. Hardware-backed texture/SRV/device-loss and release-acknowledgement tests are also still missing; implementation task 3.3.2 is complete, while the associated hardware validation tasks remain open.
